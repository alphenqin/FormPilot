# M5.1：JD 与岗位证据匹配

本轮实现 JD 解析、岗位条件审阅和本地经历证据匹配。该批次未包含简历定制；后续 M5.2 已实现，见 [岗位简历指南](RESUME_USER_GUIDE.md)。开放题已在 [M5.3](ANSWERS_USER_GUIDE.md) 实现；投递记录和多站点专有适配仍待后续。

## 操作步骤

1. 执行 `pnpm build`，重启本地 API，并在 `chrome://extensions` 重新加载扩展。打开个人资料库并解锁。
2. 在资料库展开 **M5.1 · JD 与岗位匹配**。粘贴岗位正文；或先在岗位详情页点击扩展图标授予当前页权限，然后刷新标签页列表，选择页面并读取岗位正文。只能读取有权限的 HTTP(S) 顶层页面；复杂页面可改用粘贴。
3. 核对正文范围，删除非岗位信息。页面来源 URL 会去除查询参数和普通片段；正文可能包含网站公开文字，发送前仍需本人检查。超过 20000 字符的页面会截断并明确提示，可按实际需要调整文本。
4. 连接已有本地 API，在所示供应商和政策下勾选本次授权，点击 **授权解析 JD**。模型只收到当前 JD 的文本，不收到个人资料、网页 HTML、来源 URL 或备注。JD 原文、授权检查点与结果加密保存到资料库。
5. 对照 **JD 原文** 检查岗位属性和每条要求。可以定位原文、修改分类/级别/原文关键词、删除错误属性和要求，也可从唯一出现的连续原文补充遗漏条件。修改要求后必须重新确认。原始正文保持不变；更换正文可建立新岗位。
6. 确认已核对提取项后，点击 **开始本地岗位匹配**。个人资料只在浏览器本地参与计算，待确认、已拒绝和冲突事实不会作为已确认依据。
7. 查看逐项结果、事实版本和原始材料引用。需补充时，到资料库新增或修订事实，确认后重新计算。可导出含个人资料的 Markdown 证据对照，分享前自行检查内容；整体资料库备份仍为密文。

不使用模型时，可点击 **仅保存 JD 并手动标注**，从原文补充要求、核对后本地匹配。无需模型授权或 API 连接。

## 四类结果的含义

| 结果     | 含义                                                     |
| -------- | -------------------------------------------------------- |
| 匹配     | 已确认、明确对应的事实满足这一条支持的条件               |
| 证据不足 | 有相关事实，但精度、熟练度或附加条件尚不足以证明满足     |
| 待确认   | 缺少可核对的确认事实，或需要人工语义审核                 |
| 未匹配   | 当前已确认记录明确低于或否定这条条件，不代表最终录用结论 |

系统没有综合分或“符合全部岗位资格”的判定。模型提取可能遗漏要求；确认提取项不表示本人满足要求。

学历只支持明确名称与最低等级；技能按明确名称和同一技能实体的熟练度核对。Java 不等于 JavaScript，项目描述中的关键词只作线索。年限仅对支持的工作或实习范围合并重叠区间，以日期精度计算保守边界，不将实习、项目自动当作工作，不补日期。意向城市与现居城市分开。全日制、相关行业、签证、复杂条件、职责能力等保留人工核实。

## 版本与恢复

修改岗位、修改个人资料、计算日期或规则版本变化会让旧匹配过期。历史结果保留原岗位/资料版本与事实引用，重新计算才得到当前结果；最多保留 20 个岗位、每岗位 10 个旧版本、合计 60 份分析，超过岗位历史范围的分析随修订清理。

解析过程中关闭资料库后，重新连接 API、解锁并点击 **恢复 JD 解析** 查询同一任务；不会自动创建新的付费任务。服务端 JD 结果只在内存保留 5 分钟，服务重启或到期后需取消本地检查点，再明确授权重新解析。最多保留 3 个本地待处理检查点。
