# M1 个人经历资料库实施报告

日期：2026-11-16。用户已确认开始 M1，并授权删除旧工程。当前结论：**M1 核心功能已实现，43 项测试及工程检查通过**，包括真实 DeepSeek 浏览器技术验证。PRD 要求的有授权真实简历验收尚待完成，不将合成样本冒充真实简历。

## 完成功能与复现

M1 提供扩展工作空间建立/解锁/锁定、PDF/TXT/手动文本导入、本地 PDF worker、分页原文分块、DeepSeek 解析、连续原文证据校验、候选事实确认/拒绝/编辑、来源区分、事实历史、经历实体和显式映射、冲突与时间异常提示、手动补充、加密备份恢复、修改口令及删除。

运行 `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm dev`，在 Chromium 加载 `apps/extension/dist`。点击弹窗“打开个人资料库”，建立口令并导入文本。模型配置只在服务端 `.env`；扩展输入独立的本地 API 访问令牌后，确认供应商、模型和本次文本范围，授权解析，再逐项审核。具体操作见 [README](../../Readme.md#使用-m1-资料库)。

## 目录、旧工程与核心模块

用户授权删除 `legacy/` 后已实际删除，未重新建立副本或备份，活动配置中的排除项也已清理。历史 M0 迁移文档保留当时记录并补记后续删除；当前实现无旧扩展内嵌源码打包链路，Git 远端未更改。

- `packages/domain`：文档/实体/证据/事实模型、不可变版本修订、日期精度、来源、冲突与时间规则。
- `packages/local-store`：Dexie IndexedDB、PBKDF2 校准、AES-GCM、AAD、加密备份、口令更新、CAS 与删除。
- `packages/contracts/src/profile.ts`：M1 解析、源块、授权、任务、会话与结果 schema 草案，四大 API 的最终 schema 仍按 PRD 在 M3 冻结。
- `packages/ai`：DeepSeek OpenAI 兼容 JSON Output 适配器，超时、拒绝、坏输出和引用校验，最多一次瞬时错误重试。
- `apps/api/src/profile.ts`：独立本地访问令牌授权、短期会话、异步解析、幂等、任务归属、查询/清理与 TTL。
- `apps/extension/src/workspace`：资料库 UI、本地文件导入、PDF worker 与 API 客户端。
- `tests/fixtures`：完全虚构文本/PDF 与受控模型；未将真实隐私资料入库。`scripts/smoke-provider.ts` 仅使用虚构样本做显式真实模型测试。

## 数据模型与兼容

数据库 `formpilot-vault`，Dexie schema 版本 1，单条加密快照包含原文件、源块、证据、全部事实修订、实体、解析用量和任务授权检查点。随机 data key 仅在解锁页面持有；PBKDF2 派生 wrapping key，AES-GCM IV 每次独立随机，AAD 绑定工作空间/格式/revision。KDF 校准目标约 180 ms，最少 600000、最多 2000000 次，不把密钥和密文永久保存在一起。

事实先 pending，确认产生新修订；改值为 user 来源并恢复 pending，原始证据保留但不冒充修改后值的来源。未解决冲突不进入可用已确认事实。年份、年月、日期、至今保持显式精度；不同经历实体不自动混合，多文档经历需显式映射。

M0 没有资料库记录需要迁移；M1 校验版本及引用，未来未知版本拒绝导入。备份仅恢复到空资料库，仍需原口令。旧扩展个人资料未自动迁移，删除仓库旧代码不清除用户已有浏览器数据。

## API、配置、权限与数据生命周期

新增接口见 [M1 架构决策](../adr/0002-m1-local-vault.md#api-与会话m1-草案)。服务端配置 `FORMPILOT_MODEL_PROVIDER/BASE_URL/NAME/API_KEY/DATA_POLICY_URL` 和独立 `FORMPILOT_API_TOKEN`。用户给定模型为 DeepSeek `deepseek-flash`，本地 `.env` 已配置、Git 忽略、权限 600；不在报告或客户端复述密钥。

会话 30 分钟，仅所属会话可查任务，最多 20 个短期任务、每会话 2 个并行任务，解析预算 60 秒、结果 TTL 五分钟。API 内存保存结果，不保存原简历到服务器磁盘，无 SQLite/WAL。成功本地落盘后请求删除结果；服务重启/过期报错，重新发送需授权。启动前保存原文摘要、完整授权、client_request_id，关闭页面后恢复短请求查询，不依赖 MV3 worker 常驻。

授权绑定供应商、模型、政策 URL、文本摘要、用途和时间。重新连接服务清除 UI 授权勾选，避免配置变化后复用旧授权。网页桥接仍只 pair/ping，敏感资料只在扩展 origin 管理；权限保持回环 API host，无全站 content_scripts。供应商密钥只在后端，构建检查实际 `.env` 中密钥值及配置标记未出现在客户端产物。

本地全部删除清空原文件、事实、证据、历史和检查点；尝试撤销当前 API 会话并取消它的任务。不可达时明确提示服务端短期数据最多五分钟过期；其他历史会话的短期任务同样靠 TTL 清理。无法替代供应商的数据删除政策，也不删除用户已导出的备份。

## 性能、样本与费用

- 真实 DeepSeek 直接技术测试：1 份虚构文本，7 条候选，耗时 2224.24 ms，输入 1019、输出 523 tokens。样本量仅 1，无失败率/准确率统计代表性。请求模型名为 `deepseek-flash`，未宣称锁定供应商不可变的底层权重版本。
- health：本机 20 次串行回环 HTTP，P50 2.55 ms、P95 5.04 ms；不能代表部署性能。
- 本地加密、口令更新、恢复与并发保护测试最近一次 7 项共 4.42 s；这不是单份大简历的性能预算。最大容量与复杂 PDF 的性能未做批量评估。
- 模型实际费用金额未测量；已记录输入/输出 tokens，缓存命中、折扣和供应商账单可能影响费用，不按 token 数捏造实际扣费。

## 限制、未完成验收与后续

M1 **尚未最终验收**：缺少至少一份有明确授权的真实脱敏简历及人工逐项确认记录；真实样本的解析耗时、失败率、质量与实际费用尚未测量。当前通过的是工程和虚构样本技术验证。

当前单用户回环授权不是多用户生产认证；服务器重启会丢失短期任务结果。完整快照加密适合当前容量上限，不提供大规模文档性能承诺。复杂多栏 PDF 阅读顺序、受密码保护 PDF 与无文本文件需要人工处理；没有 OCR 或 PDF 版面坐标高亮。跨文档同一教育/工作经历不自动合并，用户映射后再解决冲突，避免误绑定。
