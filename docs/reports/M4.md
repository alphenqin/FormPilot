# M4 原生填写、核验与撤销实施报告

日期：2026-11-17。用户授权开始 M4，首个真实目标为小米招聘。结论：**本地原生执行闭环与完整工程回归通过**。小米真实申请表、真实授权简历与站点联合验收尚未完成，不能宣称 M4 真实业务验收或整站适配通过。没有重建用户删除的 `.git`，没有自动提交申请。

## 已交付

- 依据服务端批准计划生成受限执行包，绑定 task/tab/frame/page/fingerprint、资料版本、plan digest、epoch 和 lease。客户端开始请求只能引用字段，不能自行指定填充值。
- SQLite 全工作空间执行锁、页面内执行锁、写前/写后加密检查点、幂等、序号守卫、停止、单字段重试与报告恢复。异步预检并发重复启动不会双写；停止/替换扫描或离开页面会结束旧执行并释放其锁，离线时保留恢复引用。
- 原生 input/textarea/date/month/select/multiple/radio/checkbox 使用原型 setter，派发 input/change；逐字段稳定回读，检查浏览器 validity/aria-invalid，最终再次回读已执行字段。
- 原值或用户编辑变化时保护字段；相关结构、路由、页面身份、人工语义标注变化使旧计划失效。资料库解锁状态与资料版本通过 options Port 每字段核对，关闭/锁定后不继续下一字段。
- 条件撤销检查写入值与编辑计数；用户改后再改回相同值，以及等待检查点期间再编辑，也不会被撤销覆盖。撤销后清除批准并回到 DRAFT。
- M3 冻结的 verify 请求/结果结构保持兼容，M4 从原 501 改为真实报告校验。报告必须逐项匹配持久检查点，未知、重复、篡改、假批准和未准备的成功项均拒绝；最终只能保留或降级成功，不能升级失败。
- 资料库提供执行、停止、核验、历史、重试、撤销与人工定位入口。显示回读结果，始终提示申请尚未提交；附件与条款在网页中人工处理。

使用步骤见 [M4 操作说明](../M4_USER_GUIDE.md)，接口见 [API 契约](../api/README.md)，设计取舍见 [ADR 0005](../adr/0005-m4-guarded-execution.md)。

## 核心代码、数据与兼容

`packages/browser-engine/src/execution.ts` 实现页面执行器；scanner 增加受限执行定位、结构守卫与人工标注修订计数。`apps/extension/src/background/execution.ts` 处理来源认证、解锁 Port、API 编排和调度元数据；content 仅接受本扩展 worker 的执行消息。`ExecutionPanel.tsx` 提供控制与报告，继续使用已有 options 资料库的解锁上下文。

`apps/api/src/execution.ts` 实现 begin/checkpoint/cancel/interrupt/verify，`packages/domain/src/execution.ts` 校验冻结报告与计划的一致性。`packages/contracts` 增加执行消息和辅助契约，生成 [execution.json](../api/v1/execution.json)。执行检查点与核验请求上限 8 MiB，字段与值仍受 schema 有界约束，避免合法大型报告在填完后被原小体积传输限制丢弃。

SQLite schema 从 v1 原地升级为 v2，新增 `execution_locks`；既有计划/幂等表保留，执行记录继续存于 AES-GCM 加密 payload，锁的身份索引采用 HMAC。仍使用独立服务端 `FORMPILOT_DATA_KEY`；没有新增第三方依赖或权限。每任务保留 20 次执行记录，计划期限 24 小时，执行 lease 最长十分钟且不超过计划期限，实际扫描/页面权限仍必须有效。

Vault v1 新增可选执行记录，旧 M1/M3 备份仍可读。发现同窗批准/同步并发保存问题后，改为串行读改写任务更新；M1 事实保存合并最新任务状态，旧响应不能回退新版本/批准/失效状态。跨窗口 CAS 与锁定 epoch 继续生效，不能用队列绕过外窗口或旧密钥保护。

`chrome.storage.session` 仅保存 API 会话及 task/tab/workspace/execution/epoch/期限等调度引用，不保存字段值；执行包和报告仅在授权内存与加密存储中。日志继续只记录请求 ID、状态和耗时。客户端实际密钥标记与最小权限构建检查通过。
