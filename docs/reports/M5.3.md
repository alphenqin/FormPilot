# M5.3：开放题回答

日期：2026-11-18。范围：用户继续推进 M5 后，本轮交付开放题的已确认材料选择、引用草稿、本人编辑、审核、复制导出与加密版本管理。投递记录、多站点专有适配和真实业务验收仍待后续。

## 完成功能与约束

- 选择已核对 JD、填写问题，显式勾选 1～16 条当前无冲突的确认事实；姓名、联系方式、性别、证书编号和薪资字段不可选，待确认/拒绝/冲突事实不会发送。展示问题、岗位标题/公司/要求和事实发送范围，单次授权绑定供应商、模型、政策、输入摘要及时间。
- 模型只选择相关事实和岗位对照标识。程序校验引用必须是所选事实的完整原值，未知标识、截掉否定词、改写数值、额外总分和空引用明确失败。最多 6 条引用，按实体组织草稿，不自由编造动机、挑战、结果或业绩。
- 草稿保留引用、材料快照、档案与岗位版本、本次授权和生成元数据。本人改写后保存，再单独审核；只改首尾空白不能算修改。本人新增陈述需本人核实，程序不自动证明其真实性，界面明确说明引用仅证明生成材料来源。
- 未修改、未保存、未审核或过期的答案不能经应用复制/导出。复制和 TXT 导出仅输出正文，不自动写入个人事实、M4 计划或申请表。修改/恢复历史清除审核；历史最多 10 个修订。
- 任务支持运行中取消、锁定/关闭后恢复、网络异常恢复。新增按原请求标识的只读恢复，即使生成 POST 响应丢失也不再次调用模型；过期或服务重启后须重新授权生成。取消后迟到结果不能写回。
- 答案和检查点沿用加密资料库、备份与恢复。上限 30 份答案与待生成任务、3 个本地检查点；生成前保留容量，避免达到本地上限后仍调用模型。删除岗位级联清理其答案及本地检查点。

这是可追溯的选材和草稿功能，最终措辞需本人编辑核实。查看未审核草稿是必要的审阅入口，应用不会声称能阻止用户手工选择文本复制。

## 代码、数据与接口

契约：`packages/contracts/src/answer.ts`；领域：`packages/domain/src/answer.ts`；模型：`generateOpenAnswer` 与 DeepSeek 的 answer_generate 提示；服务：`apps/api/src/answers.ts`；扩展：`workspace/AnswerPanel.tsx`。Vault 验证本地事实/证据快照并利用同一写队列中的最新资料进行审核。

API 契约见 [answers.json](../api/v1/answers.json)：

| 接口                                  | 用途                                        |
| ------------------------------------- | ------------------------------------------- |
| POST `/v1/career/answers/generate`    | 单次授权、幂等异步生成，返回 202            |
| GET `/v1/career/answers/jobs/:id`     | 查询原任务                                  |
| DELETE `/v1/career/answers/jobs/:id`  | 中止并清理任务                              |
| GET `/v1/career/answers/requests/:id` | 按原 client_request_id 只读恢复，不启动模型 |

session 按工作空间隔离；同资料库重新连接可查询，撤销会话清理。默认超时 60 秒、内存结果保留 5 分钟，最多 20 个缓存任务/每工作空间 2 个运行任务。请求上限 512 KiB，语义输入 120000 字符；日志保留既有白名单元数据，不记录正文。服务端只能验证所给引用和值是否一致，确认状态与真实性由扩展对照本地资料检查。

capabilities stage 为 M5.3，增加 answer_generate。旧四项业务接口和 JD API 保持兼容，无 SQLite schema、密钥或权限变更。`career.answers`、`career.answer_pending` 为可选字段，新版可读取旧资料及备份；包含新字段的备份不保证可由旧程序读取。
